## 0. 프로젝트 배경 및 목적

### 0.1 현재 상황

**보유 인프라:**
- ✅ AICC 플랫폼 운영 중
- ✅ 어드바이저(상담사) 통화 자동 STT 변환 및 저장 기능 완료
- ✅ STT 데이터 축적 중

**문제점:**
- ❌ 이전 외주 개발사를 통한 QA 화면 개발 → 제대로 진행되지 않음
- ❌ 기존 QA 시스템의 구조적 한계 (1~2% 표본 평가, 평가자 주관성)

### 0.2 프로젝트 목적

**본 프로젝트의 목표:**
> **"STT 데이터 기반 AI QA 시스템의 화면 프로토타입 제작"**

**명확한 범위 정의:**

| 구분 | 내용 |
|------|------|
| **목적** | 기획자가 QA 구성을 기획하고 **화면으로 시각화**하여 내부 공유 |
| **산출물** | 기능하는 화면 프로토타입 (UI/UX 중심) |
| **데이터** | 더미 데이터 사용 (실제 API 연동 불필요) |
| **기능 구현** | 백엔드/AI 엔진 구현 불필요 (화면만 구현) |
| **목표 사용자** | 내부 이해관계자, 개발팀 전달용 |

**프로토타입 요구사항:**
```
✅ 해야 할 것:
- UI/UX 화면 구성
- 더미 데이터로 동작 시연
- 인터랙션 (클릭, 모달, 탭 전환 등)
- 필터/정렬 등 프론트엔드 기능

❌ 하지 않아도 되는 것:
- 실제 STT 연동
- AI 평가 엔진 구현
- 백엔드 API 개발
- 데이터베이스 구축
- 실시간 데이터 연동 (30초 갱신은 시뮬레이션)
```

### 0.3 기존 인프라 활용

```
[기존 AICC 플랫폼]
      ↓
어드바이저 통화
      ↓
STT 자동 변환 ✅ (기존 기능)
      ↓
텍스트 데이터 저장 ✅ (기존 기능)
      ↓
━━━━━━━━━━━━━━━━━━━━━━━━
[신규 QA 시스템 - 본 프로젝트]
      ↓
더미 STT 데이터로 QA 화면 시연
      ↓
기획 검증 및 내부 공유
```

**기본 평가 정책:**
- 특별한 일이 없으면 **모든 통화에 QA 적용**
- 평가 계획 관리를 통해 예외 설정 가능

### 0.4 프로젝트 성공 기준

| 항목 | 기준 |
|------|------|
| **화면 완성도** | 모든 주요 화면 구현 (더미 데이터) |
| **인터랙션** | 클릭, 모달, 탭 전환 등 동작 |
| **이해도** | 이해관계자가 "이렇게 동작하는구나" 이해 |
| **전달성** | 개발팀이 기획 의도를 명확히 파악 |

**이 문서의 역할:**
- 화면 프로토타입 개발 가이드
- 내부 공유용 기획서
- 향후 실제 개발 시 요구사항 문서

## 1. Project Vision

### 1.1 핵심 목표
**"다크 데이터 98%를 0%로 - 100% 전수 평가 실현"**

기존 컨택센터 QA의 구조적 한계(1~2% 표본 평가, 평가자 주관성, 코칭 시차)를 해결하는 **AI 기반 지능형 품질 관리 플랫폼**

### 1.2 핵심 가치 제안

| 문제점 | 솔루션 |
|--------|--------|
| 98% 상담이 미분석 다크 데이터 | STT 기반 100% 전수 자동 평가 |
| 평가자별 점수 편차 (Calibration 문제) | 하이브리드 엔진의 결정론적 정확성 |
| AI 블랙박스 불신 | XAI(설명 가능한 AI) 인터페이스 |
| 평가→코칭 시차 발생 | 실시간 피드백 + My Zone 통합 |

### 1.3 기술 전략: 하이브리드(AI + NLP) 평가 엔진

```
┌─────────────────────────────────────────────────────────────┐
│                    Router Model (평가 항목 분석)              │
└─────────────────────────┬───────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│ Layer 1: NLP    │ │ Layer 2: AI     │ │ Layer 3:        │
│ Deterministic   │ │ Probabilistic   │ │ Cross-Validation│
│ ───────────────│ │ ───────────────│ │ ───────────────│
│ • 필수 고지사항  │ │ • 공감 태도     │ │ • 상호 검증     │
│ • 금지어 탐지   │ │ • 적극적 경청   │ │ • Guardrail    │
│ • 스크립트 준수 │ │ • 문맥 분석     │ │ • 이중 안전장치  │
│ • 개인정보 확인 │ │ • 감성 분석     │ │                 │
│                 │ │ • 상담 요약     │ │                 │
│ 정확도: 100%   │ │ 정확도: 95%+   │ │                 │
└─────────────────┘ └─────────────────┘ └─────────────────┘
```

### 3.1 XAI(설명 가능한 AI) 위젯

**점수 설명 툴팁**
- 점수 옆 'Why?' 아이콘/툴팁 배치
- 마우스 오버 시 자연어로 이유 설명
- 가점/감점 요인 분리 표시
- 해당 구간 재생 버튼 연동

**스크립트 하이라이트 시각화**
- 긍정 하이라이트: 초록색 배경 (공감 표현 등)

```

```

**1단 메인 메뉴 (고정):**
- 너비: 176px (w-44)
- 배경: 틸 그린 (#0F766E)
- 항상 화면에 고정
- 메인 컨텐츠는 1단 너비만큼만 마진

```
AICC 플랫폼
├─ 에이전트 빌더
├─ 상담 어드바이저
├─ AICM
├─ TA
└─ QA ◀ 마우스 오버 시 2단 열림
```

**2단 서브메뉴 (오버레이):**
- 너비: 320px (w-80)
- 배경: 흰색
- **마우스 오버 시에만 표시** (기본 숨김)
- 그림자: `box-shadow: 8px 0 30px rgba(0,0,0,0.15)`
- 메인 컨텐츠 위에 떠 있는 오버레이 형태

```
QA
├─ 홈
│   ├─ QA 대시보드
│   └─ 평가 현황
├─ 평가 관리
│   ├─ 평가 항목 관리
│   └─ 평가표 관리
├─ 분석
│   ├─ 상세 분석
│   ├─ 트렌드 분석
│   └─ 리포트 생성기
├─ 이의 제기 처리함
├─ 시스템 설정
├─ ━━━━━━━━━━━━━━━
├─ 나의 성과 대시보드
├─ 나의 평가 결과
├─ 나의 이의 제기 현황
└─ 코칭 관리 (추후)
```

**마우스 오버 동작:**
1. 1단 메뉴의 "QA" 항목에 마우스 오버 → 2단 서브메뉴 표시
2. 서브메뉴 안에 마우스가 있으면 계속 표시 유지
3. 서브메뉴에서 마우스가 벗어나면 150ms 후 숨김
4. 메인 컨텐츠 영역에 영향 없음 (오버레이로 떠 있음)

## 6. 디자인 참고 (기존 AICC 플랫폼)

### 6.1 기존 플랫폼 화면 분석

**참고 이미지 1: AICC 플랫폼 메인 화면**

**주요 특징:**
- ✅ 왼쪽 사이드 메뉴 (약 200px, 고정 위치)
- ✅ ELP 로고 상단 배치
- ✅ 메뉴 검색 기능
- ✅ 계층적 메뉴 구조 (AICC 플랫폼 > QA)
- ✅ 틸 그린 계열 브랜드 컬러 (`#0F766E`)
- ✅ 활성 메뉴 녹색 배경 처리
- ✅ 메뉴 아이콘 + 텍스트 조합

**적용 방법:**
```
QA 메뉴는 "AICC 플랫폼" 하위에 추가
→ 클릭 시 서브메뉴 펼침/접힘
→ QA 홈, 평가 관리, 분석, 이의 제기, 설정
```

**참고 이미지 2: 리스트 형식 화면 (평가 항목 관리)**

**주요 특징:**
- ✅ 상단 탭 네비게이션 (대시보드, 평가 항목 관리 등)
- ✅ 검색 조건 섹션 (접기/펴기 가능)
- ✅ 테이블 리스트 형식
  - 체크박스 (일괄 작업용)
  - 상태 배지 (수동, CHAT, CALL 등)
  - 평가 방식 배지 (AI: 주황색, NLP: 파란색)
  - 가감점 수치 표시
  - 상태 (사용/미사용)
- ✅ 하단 페이지네이션
  - 이전/다음 버튼
  - 페이지 번호
  - 페이지당 건수 선택 (30건, 50건 등)
- ✅ 우측 상단 액션 버튼 (검색, 저장 등)

**적용 방법:**
```
모든 리스트 화면에 이 디자인 패턴 적용:
- 평가 항목 관리
- 평가표 관리
- 평가 결과 상세
- 이의 제기 처리함
- 프롬프트 템플릿 라이브러리
```

### 6.2 디자인 일관성 체크리스트

**모든 화면이 지켜야 할 규칙:**

| 구분 | 필수 요소 |

function onWorkspaceChange(workspaceId) {
  const teamSelect = document.getElementById('team-select');
  
  if (workspaceId === 'all') {
    // 전체 선택 시 팀 필터 비활성화

    teamSelect.value = 'all';

    const workspace = workspaces.find(ws => ws.id === workspaceId);

    // 팀 옵션 동적 생성
