## 0. 프로젝트 배경 및 목적

### 0.1 현재 상황

**보유 인프라:**
- ✅ AICC 플랫폼 운영 중
- ✅ 어드바이저(상담사) 통화 자동 STT 변환 및 저장 기능 완료
- ✅ STT 데이터 축적 중

**문제점:**
- ❌ 이전 외주 개발사를 통한 QA 화면 개발 → 제대로 진행되지 않음
- ❌ 기존 QA 시스템의 구조적 한계 (1~2% 표본 평가, 평가자 주관성)

### 0.2 프로젝트 목적

**본 프로젝트의 목표:**
> **"STT 데이터 기반 AI QA 시스템의 화면 프로토타입 제작"**

**명확한 범위 정의:**

| 구분 | 내용 |
|------|------|
| **목적** | 기획자가 QA 구성을 기획하고 **화면으로 시각화**하여 내부 공유 |
| **산출물** | 기능하는 화면 프로토타입 (UI/UX 중심) |
| **데이터** | 더미 데이터 사용 (실제 API 연동 불필요) |
| **기능 구현** | 백엔드/AI 엔진 구현 불필요 (화면만 구현) |
| **목표 사용자** | 내부 이해관계자, 개발팀 전달용 |

**프로토타입 요구사항:**
```
✅ 해야 할 것:
- UI/UX 화면 구성
- 더미 데이터로 동작 시연
- 인터랙션 (클릭, 모달, 탭 전환 등)
- 필터/정렬 등 프론트엔드 기능

❌ 하지 않아도 되는 것:
- 실제 STT 연동
- AI 평가 엔진 구현
- 백엔드 API 개발
- 데이터베이스 구축
- 실시간 데이터 연동 (30초 갱신은 시뮬레이션)
```

### 0.3 기존 인프라 활용

```
[기존 AICC 플랫폼]
      ↓
어드바이저 통화
      ↓
STT 자동 변환 ✅ (기존 기능)
      ↓
텍스트 데이터 저장 ✅ (기존 기능)
      ↓
━━━━━━━━━━━━━━━━━━━━━━━━
[신규 QA 시스템 - 본 프로젝트]
      ↓
더미 STT 데이터로 QA 화면 시연
      ↓
기획 검증 및 내부 공유
```

**기본 평가 정책:**
- 특별한 일이 없으면 **모든 통화에 QA 적용**
- 평가 계획 관리를 통해 예외 설정 가능

### 0.4 프로젝트 성공 기준

| 항목 | 기준 |
|------|------|
| **화면 완성도** | 모든 주요 화면 구현 (더미 데이터) |
| **인터랙션** | 클릭, 모달, 탭 전환 등 동작 |
| **이해도** | 이해관계자가 "이렇게 동작하는구나" 이해 |
| **전달성** | 개발팀이 기획 의도를 명확히 파악 |

**이 문서의 역할:**
- 화면 프로토타입 개발 가이드
- 내부 공유용 기획서
- 향후 실제 개발 시 요구사항 문서

## 1. Project Vision

### 1.1 핵심 목표
**"다크 데이터 98%를 0%로 - 100% 전수 평가 실현"**

기존 컨택센터 QA의 구조적 한계(1~2% 표본 평가, 평가자 주관성, 코칭 시차)를 해결하는 **AI 기반 지능형 품질 관리 플랫폼**

### 1.2 핵심 가치 제안

| 문제점 | 솔루션 |
|--------|--------|
| 98% 상담이 미분석 다크 데이터 | STT 기반 100% 전수 자동 평가 |
| 평가자별 점수 편차 (Calibration 문제) | 하이브리드 엔진의 결정론적 정확성 |
| AI 블랙박스 불신 | XAI(설명 가능한 AI) 인터페이스 |
| 평가→코칭 시차 발생 | 실시간 피드백 + My Zone 통합 |

### 1.3 기술 전략: 하이브리드(AI + NLP) 평가 엔진

```
┌─────────────────────────────────────────────────────────────┐
│                    Router Model (평가 항목 분석)              │
└─────────────────────────┬───────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│ Layer 1: NLP    │ │ Layer 2: AI     │ │ Layer 3:        │
│ Deterministic   │ │ Probabilistic   │ │ Cross-Validation│
│ ───────────────│ │ ───────────────│ │ ───────────────│
│ • 필수 고지사항  │ │ • 공감 태도     │ │ • 상호 검증     │
│ • 금지어 탐지   │ │ • 적극적 경청   │ │ • Guardrail    │
│ • 스크립트 준수 │ │ • 문맥 분석     │ │ • 이중 안전장치  │
│ • 개인정보 확인 │ │ • 감성 분석     │ │                 │
│                 │ │ • 상담 요약     │ │                 │
│ 정확도: 100%   │ │ 정확도: 95%+   │ │                 │
└─────────────────┘ └─────────────────┘ └─────────────────┘
```

**평가 방식 3가지:**

| 평가 방식 | 명칭 | 설명 | 적용 항목 예시 |
|----------|------|------|---------------|
| **🖐️ Manual** | 수동 평가 | 관리자가 직접 청취 후 평가 | - |
| **🔧 Auto-NLP** | NLP 규칙 기반 | 키워드/패턴 매칭 (100% 정확도) | 필수 고지사항, 금지어, 스크립트 준수, 개인정보 확인 |
| **🧠 Auto-AI** | AI 자동 평가 | LLM 기반 문맥 이해 (95%+ 정확도) | 공감 태도, 적극적 경청, 문맥 분석, 감성 분석 |

**메뉴 네비게이션 규칙:**

- 활성 메뉴: 틸 그린 배경 (`#0F766E`)
- 비활성 메뉴: 투명 배경

### 2.2 권한별 메뉴 표시 규칙

**동일한 QA 메뉴, 권한에 따라 다르게 표시:**

#### **👑 관리자 로그인 시**

```
✅ QA
   ├─ 📊 QA 홈                    ✅ 표시
   ├─ 📝 평가 관리                 ✅ 표시
   ├─ 📈 분석                      ✅ 표시
   ├─ ⚠️ 이의 제기 처리함           ✅ 표시
   ├─ ⚙️ 시스템 설정               ✅ 표시
   ├─ ━━━━━━━━━━━━━━━━━━━━━━
   ├─ 👤 나의 성과 대시보드         ✅ 표시 (본인 데이터)
   ├─ 📋 나의 평가 결과             ✅ 표시 (본인 데이터)
   └─ ⚠️ 나의 이의 제기 현황        ✅ 표시 (본인 데이터)
```

#### **👥 상담사 로그인 시**

```
✅ QA
   ├─ 📊 QA 홈                    ❌ 숨김
   ├─ 📝 평가 관리                 ❌ 숨김
   ├─ 📈 분석                      ❌ 숨김
   ├─ ⚠️ 이의 제기 처리함           ❌ 숨김
   ├─ ⚙️ 시스템 설정               ❌ 숨김
   ├─ (구분선 없음)
   ├─ 👤 나의 성과 대시보드         ✅ 표시
   ├─ 📋 나의 평가 결과             ✅ 표시
   └─ ⚠️ 나의 이의 제기 현황        ✅ 표시
```

**권한 구분:**

| 권한 | 역할 | 표시 메뉴 |
|------|------|----------|
| **👑 관리자** | QA 담당자, 팀장, 센터장 | 모든 메뉴 (관리자용 + 상담사용) |
| **👥 상담사** | 어드바이저(콜 상담사) | 상담사용 메뉴만 (My Zone) |

| EI-02 | 평가 항목 생성/편집 | 항목명, 설명, 기본 배점, 평가 방식 설정 |

| 기능 ID | 기능명 | 상세 설명 |
