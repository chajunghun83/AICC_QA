# 04. 개선 이행 관리 시나리오

> 이 문서는 **리포트 생성기의 개선 제안 → 개선 이행 관리** 순환 흐름을 설명합니다.
> TA/QA 모듈 모두 동일한 구조로 적용됩니다.

---

## 1. 순환 흐름 개요

```
  ┌─────────────────────────────────────────────────────────────┐
  │                                                             │
  │  ① 리포트 생성                                              │
  │     → AI가 분석 결과 기반으로 "개선 제안" 항목 자동 생성     │
  │                                                             │
  │  ② 관리자가 개선 제안 편집                                   │
  │     → 항목 삭제 / 수동 추가 가능                             │
  │                                                             │
  │  ③ "개선 제안 확정" 버튼 클릭                                │
  │     → 개선 이행 관리 DB에 저장                               │
  │                                                             │
  │  ④ 개선 이행 관리 페이지에서 처리                            │
  │     → 담당자 배정, 상태 관리(미이행→진행중→완료), 메모 기록  │
  │                                                             │
  │  ⑤ 다음 리포트 생성 시                                      │
  │     → "전기 개선 이행 현황 > 불러오기"로 이전 이행 항목 조회 │
  │     → 선택한 항목이 리포트에 이행 현황으로 포함              │
  │                                                             │
  │  ① 로 돌아감 (반복)                                         │
  └─────────────────────────────────────────────────────────────┘
```

### 핵심 원칙

| 원칙 | 설명 |
|------|------|
| 조직 공유 | 개선 이행 데이터는 특정 관리자에 종속되지 않으며, 모든 관리자가 동일한 목록을 조회 |
| 유형 독립 | 일간 리포트에서 확정된 제안도 월간 리포트의 "불러오기"에서 조회 가능 |
| 이력 추적 | 모든 상태 변경은 타임라인(처리 이력)으로 기록 |

## 2. 리포트 생성기 — 개선 제안 섹션

리포트 생성기의 "포함 섹션" 중 **개선 제안** 체크박스(`sec-improvement`)에 해당하는 영역.

### 2.1 동작 흐름

1. 리포트 생성 시 AI가 분석 결과 기반으로 개선 제안 항목 자동 생성
2. 각 항목에 출처 배지 표시
   - **AI** (파란색 배지): AI 자동 생성 항목
   - **수동** (회색 배지): 관리자가 직접 추가한 항목
3. 관리자 편집
   - **삭제**: 각 항목의 X 버튼 클릭
   - **추가**: "+ 항목 추가" 버튼 → 모달에서 내용 입력 → `source: 'manual'`로 추가
4. **"개선 제안 확정"** 버튼 클릭 (항목 추가 버튼 오른쪽에 위치)
   - 확인 모달: 확정할 항목 목록 + 리포트 유형/기간 표시
   - "확정" 클릭 → 개선 이행 관리 DB에 신규 레코드 생성

### 2.2 확정 시 전달 데이터

리포트가 이미 생성된 뒤이므로 리포트 유형과 기간을 확정하여 함께 저장합니다.

```json
{
  "reportType": "월간",
  "periodFrom": "2025-03-01",
  "periodTo": "2025-03-31",
  "contents": ["제안 내용 1", "제안 내용 2", "제안 내용 3"],
  "sources": ["ai", "ai", "manual"],
  "confirmedBy": "관리자ID"
}
```

### 2.3 데이터 구조

```javascript
// 개선 제안 항목
{ content: '개선 제안 내용 텍스트', source: 'ai' | 'manual' }
```

## 3. 리포트 생성기 — 전기 개선 이행 현황 섹션

리포트 생성기의 "포함 섹션" 중 **전기 개선 이행 현황** 체크박스(`sec-prev-improvement`)에 해당하는 영역.
이전 기간에 확정된 개선 제안의 이행 상황을 리포트에 포함시키는 기능.

### 3.1 동작 흐름

1. 체크박스 옆 **"불러오기" 버튼** 클릭
2. 모달이 열리며 개선 이행 관리 DB에서 항목 조회
   - 필터: 상태 (전체/미이행/진행중/완료), 키워드 검색
3. 테이블에서 **행 클릭으로 선택/해제** (체크박스 없음, 행 하이라이트 + ✓ 표시)
4. "선택 완료" 클릭 → 선택한 항목이 리포트 프리뷰에 반영

### 3.2 리포트 출력 테이블

| 컬럼 | 설명 |
|------|------|
| 유형 | 리포트 유형 배지 (일간: 파랑, 주간: 초록, 월간: 보라) |
| 기간 | 해당 리포트의 분석 기간 |
| 개선 제안 내용 | contents 배열을 번호 매겨 표시 (1. xxx / 2. xxx / ...) |
| 담당자 | 이행 담당자 |
| 상태 | 완료(초록) / 진행중(주황) / 미이행(빨강) 배지 |
| 처리 메모 | 담당자의 처리 메모 |

## 4. 개선 이행 관리 페이지

리포트 생성기에서 확정된 개선 제안 항목을 관리하는 독립 페이지.

### 4.1 페이지 위치

| 모듈 | 메뉴 경로 | 파일 |
|------|----------|------|
| TA | 관리자 기능 > 개선 이행 관리 | `pages/ta/improvement-manage.html` |
| QA | (동일 구조로 구현 예정) | `pages/admin/improvement-manage.html` |

### 4.2 검색 필터

| 필터 | 타입 | 설명 |
|------|------|------|
| 기간 (시작/종료) | date | 리포트 기간 기준 필터 |
| 상태 | select | 전체 / 미이행 / 진행중 / 완료 |
| 리포트 유형 | select | 전체 / 일간 / 주간 / 월간 |

### 4.3 목록 테이블

| 컬럼 | 설명 |
|------|------|
| NO | 자동증가 PK, 내림차순 정렬 |
| 리포트 유형 | 색상 배지 (일간: 파랑, 주간: 초록, 월간: 보라) |
| 리포트 기간 | 시작~종료일 표시 |
| 개선 제안 내용 | 번호 매긴 목록으로 전체 항목 표시 |
| 담당자 | 이행 담당자 이름 |
| 상태 | 미이행 / 진행중 / 완료 배지 |
| 처리일 | 완료 처리된 날짜 |
| 처리내역 | "처리내역" 버튼 → 상세 모달 열기 |

### 4.4 처리내역 모달

좌우 분할 레이아웃:

**좌측 — 개선 제안 정보**
- 리포트 유형 (배지)
- 리포트 기간
- 개선 제안 내용 (번호 매긴 목록)

**우측 — 처리 관리**
- 담당자 (드롭다운)
- 상태 (드롭다운: 미이행 / 진행중 / 완료)
- 처리 메모 (textarea)
- 저장 버튼

**하단 — 처리 이력 타임라인**
- 시간순으로 모든 상태 변경 이력 표시
- 각 이력 항목: 일시, 처리자, 상태 배지, 메모

## 5. 데이터 모델

### 5.1 개선 이행 관리 테이블 (improvements)

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `id` | INT (PK) | 자동증가 |
| `report_type` | VARCHAR(10) | '일간' \| '주간' \| '월간' \| '연간' \| '기간지정' |
| `period_from` | DATE | 리포트 기간 시작일 |
| `period_to` | DATE | 리포트 기간 종료일 |
| `contents` | JSON (Array) | 개선 제안 내용 배열 |
| `sources` | JSON (Array) | 각 content의 출처 ('ai' \| 'manual') |
| `admin` | VARCHAR(50) | 이행 담당자 |
| `status` | VARCHAR(10) | '미이행' \| '진행중' \| '완료' |
| `confirmed_by` | VARCHAR(50) | 확정한 관리자 |
| `confirmed_at` | DATETIME | 확정 일시 |
| `completed_at` | DATE | 완료 처리일 (NULL 가능) |
| `created_at` | DATETIME | 생성 일시 |
| `updated_at` | DATETIME | 최종 수정 일시 |

### 5.2 처리 이력 테이블 (improvement_history)

| 필드명 | 타입 | 설명 |
|--------|------|------|
| `id` | INT (PK) | 자동증가 |
| `improvement_id` | INT (FK) | improvements.id 참조 |
| `admin` | VARCHAR(50) | 처리자 |
| `status` | VARCHAR(10) | 변경된 상태 |
| `memo` | TEXT | 처리 메모 |
| `created_at` | DATETIME | 이력 생성 일시 |

## 6. API 엔드포인트 설계 가이드

### 6.1 목록 조회

```
GET /api/improvements
```

| 파라미터 | 타입 | 필수 | 설명 |
|----------|------|------|------|
| `status` | string | N | 상태 필터 ('미이행' \| '진행중' \| '완료') |
| `report_type` | string | N | 리포트 유형 필터 |
| `keyword` | string | N | 개선 제안 내용 키워드 검색 |
| `date_from` | date | N | 기간 필터 시작일 |
| `date_to` | date | N | 기간 필터 종료일 |
| `page` | int | N | 페이지 번호 (기본 1) |
| `size` | int | N | 페이지 크기 (기본 10) |

**사용처**: 개선 이행 관리 페이지, 리포트 생성기 "불러오기" 모달

### 6.2 개선 제안 확정 (리포트 생성기 → 개선 이행 관리)

```
POST /api/improvements
```

```json
{
  "reportType": "월간",
  "periodFrom": "2025-03-01",
  "periodTo": "2025-03-31",
  "contents": ["VIP 고객 전용 상담 라인 신설", "야간 상담사 추가 배치 검토"],
  "sources": ["ai", "manual"],
  "confirmedBy": "박관리자"
}
```

**처리 로직**
1. `improvements` 테이블에 신규 레코드 생성 (status: '미이행', admin: NULL)
2. `improvement_history` 테이블에 초기 이력 생성 (status: '미이행', memo: '리포트에서 확정')

### 6.3 이행 처리 업데이트

```
PUT /api/improvements/:id
```

```json
{
  "admin": "김관리",
  "status": "진행중",
  "memo": "관련 부서 협의 진행 중"
}
```

**처리 로직**
1. status, admin, updated_at 업데이트
2. status가 '완료'인 경우 completed_at에 현재 일시 설정
3. `improvement_history`에 이력 추가

### 6.4 단건 상세 조회

```
GET /api/improvements/:id
```

## 7. TA/QA 공유 컴포넌트

아래 요소는 TA/QA 모듈에서 **동일한 코드**를 공유할 수 있습니다:

- 개선 이행 관리 페이지 전체 (테이블, 필터, 모달)
- 개선 제안 확정 로직 (리포트 생성기 내)
- 전기 개선 이행 현황 불러오기 모달 (리포트 생성기 내)
- 처리 이력 타임라인 컴포넌트
- 상태 배지 스타일 (미이행/진행중/완료)
- 리포트 유형 배지 스타일 (일간/주간/월간)

## 8. 프로토타입 참고 사항

| 항목 | 프로토타입 구현 | 실제 구현 시 |
|------|-----------------|-------------|
| 개선 이행 관리 목록 | `generateData()` JS 함수 | GET API 조회 |
| AI 개선 제안 | `REPORT_DATA.improvements` 하드코딩 | AI 엔진 연동 |
| 불러오기 목록 | `IMPROVEMENT_POOL` 상수 | GET API 조회 |
| 확정 저장 | 토스트 메시지만 표시 | POST API 호출 |
| 처리 업데이트 | 메모리 내 상태 변경 | PUT API 호출 |

> 소스 코드의 주석에 각 API 연동 포인트가 표시되어 있습니다.
> `report-generator.html`과 `improvement-manage.html`의 `<script>` 상단 블록 주석을 참조하세요.
